#### Phase 2: 服務邏輯層重構 (`services.py`)
**目標：** 修復舊型 Fallback 與圖表渲染邏輯，確保數據缺失時的處理是乾淨且可預期的。

**核心邏輯修正：** 將資料獲取與業務判斷分離，並優化錯誤狀態傳遞。

```python
# services.py (get_latest_investor_data)

def get_latest_investor_data(stock_code: str):
    """
    調用 mySQL_OP 取得數據，並根據業務規則進行處理。
    """
    raw_data = mySQL_OP.get_latest_investor_data(stock_code)

    if raw_data is None or "error" in raw_data:
        # [修復舊型 Fallback]：當數據層返回錯誤或空值時，不應直接傳遞給圖表渲染。
        # 而是應該返回一個標準化的「無資料」狀態標記。
        print(f"Warning: No valid investor data found for {stock_code}. Using default empty state.")
        return {"status": "NO_DATA", "data": None}

    # [圖表渲染邏輯修正]：確保返回的數據結構是圖表組件預期的格式。
    try:
        processed_data = process_for_chart(raw_data)
        return {"status": "SUCCESS", "data": processed_data}

        return {"status": "PROCESSING_ERROR", "message": str(e)}
```
